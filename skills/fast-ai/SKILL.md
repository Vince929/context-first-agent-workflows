# Fast AI — 技能包总入口

本技能只做任务判定与转交，不直接完成编码、重构或写文档；执行细节与验证策略由对应子技能定义。

> 子技能统一使用 `fast-ai-` 前缀；源码目录名、`SKILL.md` 的 `name`、安装目录名和路由名称保持一致。总入口与四个子技能平铺在同一个技能发现目录下。

## 判定与路由

1. 用户已明确指定技能或模式时，遵循用户指定；纯通用知识问答、与项目无关的闲聊正常回答即可。
2. 其余任务按**主要交付物**选择下表中的子技能。
3. 命中后，**立即加载对应子技能并遵循其边界、输出与收尾规则**，不得只声明路由而不加载。使用宿主提供的技能调用能力；若无专用能力，读取对应的 `SKILL.md`。

| 主要交付物 / 任务特征 | 路由到 |
| --- | --- |
| 项目内实现、修改、定位、排查、澄清、代码阅读，以及基于真实报错的最小修复 | `fast-ai-code` |
| 模块迁移、目录 / 边界治理、专门的文件拆分或代码去重、架构调整 | `fast-ai-refactor` |
| 用户明确要求创建 / 生成 / 更新项目地图或 `PROJECT-MAP.md` | `fast-ai-map` |
| 撰写或修订可审阅的 Markdown 文档：技术设计、架构、API、研究、结论、复盘、迁移 / 发布方案 | `fast-ai-doc` |

## 优先级与例外

- 涉及模块边界调整、跨模块契约变更、批量文件搬迁的，走 `fast-ai-refactor`，先出计划、等批准；不因任务复杂就升级为重构。
- 用户明确要求的局部外部契约变更，若不涉及上述重构条件，走 `fast-ai-code`，检查直接调用方与兼容性影响。
- 单个业务文件过大：本轮实现顺带按职责最小拆分 → `fast-ai-code`；专门的目录 / 边界治理 → `fast-ai-refactor`。
- 项目地图只按明确要求生成或更新，不作为编码任务的附带步骤。
- 一次任务选择一个主技能；同时包含代码与文档时，先按主交付物执行。确需多个技能时按顺序串行加载并说明顺序；重构先出计划，文档通常在实现确定后处理。

## 默认调用提示词

可将以下提示词放入 agent 的全局规则或项目规则：

```text
默认协作模式：每次收到项目相关任务，先加载 fast-ai 判断应使用哪个子技能，并立即加载该子技能执行；
除非我明确指定其它技能或模式。通用知识问答 / 与项目无关的闲聊不启用。
```
